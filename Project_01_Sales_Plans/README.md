# Автоматизация расчёта индивидуальных планов продаж

> SQL Server · T-SQL · Data Automation · BI

## 📌 О проекте

Автоматизация ежемесячного расчёта индивидуальных планов продаж для 300–400 сотрудников.

Изначально расчёт выполнялся в Excel и требовал значительного количества ручной обработки. Логика расчёта зависела от кадровых изменений, периодов отсутствия сотрудников, производственного календаря, коэффициентов и других организационных параметров.

В рамках проекта расчётная модель была полностью перенесена из Excel в SQL Server и подключена к BI.

---

## 🎯 Задача

Необходимо было автоматизировать расчёт планов и исключить ручную обработку при каждом пересчёте.

Модель должна была учитывать:

- кадровые изменения;
- периоды отсутствия сотрудников;
- отпуск, больничный, декрет и другие статусы отсутствия;
- производственный календарь;
- количество рабочих дней;
- коэффициенты и организационные параметры;
- изменения состава сотрудников;
- изменения руководящих позиций;
- корректирующие показатели на разных уровнях;
- постоянно изменяющиеся исходные данные.

---

## 🛠 Что было сделано

### 1. Перенос расчёта из Excel в SQL

Вся основная логика расчёта была переписана на T-SQL в SQL Server.

Вместо ручной последовательности действий в Excel была создана единая расчётная модель, которая автоматически формирует планы по сотрудникам.

Использовались:

- CTE;
- JOIN;
- оконные функции;
- CASE;
- агрегирование;
- работа с датами и периодами;
- производственный календарь.

---

### 2. Автоматизация кадровых данных

Для расчёта были организованы две автоматические выгрузки из кадровых систем:

- список сотрудников;
- информация о периодах отсутствия сотрудников.

Это позволило исключить ручную подготовку кадровых данных.

---

### 3. Обработка периодов отсутствия

Отдельно была реализована логика расчёта отсутствий.

Например, если сотрудник отсутствовал с 20.01 по 10.02, система автоматически:

1. получает дату начала и дату окончания отсутствия;
2. определяет статус отсутствия;
3. обращается к производственному календарю;
4. рассчитывает количество рабочих дней отсутствия;
5. распределяет дни между соответствующими месяцами;
6. отдельно фиксирует дни по типу отсутствия;
7. учитывает полученные значения при расчёте плана.

Таким образом, периоды отсутствия корректно учитываются даже при переходе из одного месяца в другой.

---

### 4. Справочная модель

Было создано 7 справочников, содержащих коэффициенты и другие параметры, используемые в расчёте.

Бизнес-параметры были отделены от SQL-кода.

Это позволяет изменять суммы, коэффициенты и другие значения непосредственно в справочниках без изменения SQL-кода.

После изменения параметров планы автоматически пересчитываются при следующем обновлении данных.

---

### 5. Учёт кадровых и организационных изменений

В расчёте реализована отдельная бизнес-логика для изменений в составе сотрудников и руководящих позициях.

Например, если руководитель уходит, его план снимается с учётом даты ухода.

Также модель учитывает:

- изменения состава сотрудников;
- вакантные руководящие позиции;
- организационные параметры;
- корректирующие показатели на разных уровнях.

---

### 6. Интеграция с BI

После переноса расчёта в SQL результат был подключён к BI.

Сейчас данные обновляются автоматически один раз в день утром.

При каждом обновлении система получает актуальные исходные данные, применяет бизнес-правила и формирует актуальные планы.
